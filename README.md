# CARDI

以 iOS 深色模式為主體的信用卡 PWA。依序回答三個問題：我刷滿了沒、手上的卡有什麼優惠、海外這筆刷哪張。Next.js、Vercel 與 Neon PostgreSQL。

本網站採共用帳簿模式：所有訪客都能查看、編輯、刪除同一份資料。資料庫密碼只存放在伺服器的環境變數，不會傳送到瀏覽器。

## 功能

四個分頁加一顆 ＋ 記一筆，分頁保留捲動位置，切回來是瞬間的：

- **額度**：滑動牌組第一張是總覽（本期還可領回饋、已滿／快滿／可刷／滿額），依「已滿 → 快滿 → 還能刷 → 消費滿額」列出所有活動，不用滑就知道狀況。滑到單張卡看該卡活動與最近消費。已滿的活動顯示何時重置、超刷多少；快到上限時依目前速度預估哪天刷滿。
- **優惠**：輸入通路與金額，依「這筆實際拿得到多少」比較所有卡：同卡加碼相加、切換型方案取最高、已用滿的上限不計。沒輸入時列出需要登錄的活動、30 天內到期的優惠與各卡清單。若有沒持有的卡在這個通路更高，會列在最後。
- **卡庫**：50 張主流卡的回饋、上限、年費與首刷禮，可依通路搜尋與篩選。依你記錄的消費重算「過去用這張會多拿多少」並排序，資料少時不換算成一年。持有的卡一鍵加入，有上限的優惠自動轉成額度追蹤。
- **匯率**：11 種幣別的 Visa／Mastercard／JCB 刷卡匯率與含手續費試算，並列出在當地刷哪張扣掉回饋後最便宜。
- **記一筆**：金額 → 在哪裡刷 → 卡片已依這筆排好。辨識出通路時自動勾選對應活動；辨識不出時保留全部當期活動讓你調整。存檔前就會顯示這筆是否超過上限，存檔後可復原。

邏輯集中在 `lib/`：

| 檔案 | 內容 |
| --- | --- |
| `ledger.ts` | 週期、進度、以分為單位的金額計算；回饋超過上限的部分不算已領 |
| `insights.ts` | 狀態、總覽、重置日與速度預估 |
| `channels.ts` | 通路比對：別名、類別、海外判斷，與一般消費的適用範圍 |
| `advise.ts` | 這筆刷哪張、該計入哪些活動、對各活動的影響 |
| `catalog.ts` | 卡庫比對、回放消費試算，與加入帳簿 |

## 本機與部署

1. `npm ci`
2. 不填 `DATABASE_URL` 也能開發：資料讀寫 `work/local-ledger.json`（不進版控，可放一份 `work/seed-ledger.json` 當起始資料），雲端帳簿不受影響，卡面圖片唯讀借用線上版。要連資料庫時複製 `.env.example` 為 `.env.local`，填入 Neon 的 `DATABASE_URL`，再執行 `node scripts/migrate.mjs`。
3. `npm run dev`；測試 `npm test`；正式建置 `npm run build`。
4. Vercel 匯入此儲存庫，設定 `DATABASE_URL`，框架選 Next.js。

資料表結構由 `db/schema.ts` 管理。修改後使用 `npm run db:generate` 產生新的遷移檔，不覆寫已套用檔案。帳簿內容存在單一 JSON 欄位，新增的選填欄位（例如 `catalogId`）不需要遷移。

所有金額為 NT$。日期與週期依 Asia/Taipei；帳單週期含結帳日，次日為新週期。查看日期用來選定週期，進度包含整個週期已記錄的消費。回饋金額依各活動比例估算；選填實際回饋時，同一金額分別採用於每個勾選的回饋活動，消費滿額不使用此欄位。

iOS：使用 Safari 開啟網站，選擇「分享 → 加入主畫面」。Service Worker 快取建置檔，開啟不必等網路；帳簿資料另存於裝置，再於背景同步。

## 卡片資料庫

見 [docs/catalog.md](docs/catalog.md)。匯率來源見 [docs/exchange-rates.md](docs/exchange-rates.md)。

官方卡面可依名稱配對，或按「從官網抓卡面」下載壓縮後存入雲端；來源連結記錄於 `lib/card-images.ts`。圖片失效時自動回退至簡約卡面。卡庫中的卡片一律使用依銀行上色的繪製卡面，不連結銀行圖片。
